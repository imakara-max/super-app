# きょうの予定

Google アカウントでログインし、Google カレンダーの **今日の予定** を一覧表示する Web アプリです。
iPhone の Safari から「ホーム画面に追加」すると、アプリのように全画面で起動できます (PWA)。

- ビルド不要の静的サイト (HTML / CSS / JavaScript のみ)
- サーバー不要。ブラウザから直接 Google Calendar API を呼び出します
- 権限は読み取り専用 (`calendar.readonly`)
- 「今日・明日・今週（今日から 7 日間）」を切り替えて表示。今週は日ごとに見出し付きで表示
- 登録しているカレンダーの予定をまとめて表示（自分が「不参加」にした予定は除外）
- 右上の設定ボタンで表示するカレンダーを選べる（選択はその端末に保存）
- 進行中の予定を強調、終了した予定は薄く表示。タップで Google カレンダーの予定を開く
- ダークモード対応、オフライン時もアプリ画面は起動

## セットアップ

### 1. 公開 URL を決める（GitHub Pages）

iPhone のホーム画面アプリと Google ログインには HTTPS が必要です。

1. GitHub のリポジトリ → **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
2. `main`（または `master`）ブランチに push すると自動デプロイされます
3. 公開 URL は `https://<ユーザー名>.github.io/<リポジトリ名>/` になります
   （例: `https://imakara-max.github.io/super-app/`）

> GitHub Pages は無料プランの場合、公開リポジトリでのみ利用できます。

### 2. Google Cloud で OAuth クライアントを作る

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. **API とサービス → ライブラリ** で「Google Calendar API」を有効化
3. **Google Auth Platform（OAuth 同意画面）** を設定
   - ユーザーの種類: 外部
   - スコープ: `.../auth/calendar.readonly`, `openid`, `email`
   - 公開ステータスが「テスト」の間は、**テストユーザー** に自分の Google アカウントを追加
4. **クライアント → クライアントを作成**
   - アプリケーションの種類: **ウェブ アプリケーション**
   - 承認済みの JavaScript 生成元: `https://<ユーザー名>.github.io`
   - 承認済みのリダイレクト URI: `https://<ユーザー名>.github.io/<リポジトリ名>/`（**末尾のスラッシュまで完全一致**）
   - ローカル確認用に `http://localhost:8000` と `http://localhost:8000/` も追加しておくと便利
5. 発行された **クライアント ID** を `config.js` の `GOOGLE_CLIENT_ID` に貼り付けて push

クライアント ID は公開されても問題ない値です（クライアントシークレットは使いません）。

### 3. iPhone のホーム画面に追加

1. iPhone の **Safari** で公開 URL を開く
2. 共有ボタン → **ホーム画面に追加**
3. ホーム画面のアイコンから起動し、「Google でログイン」

## メール機能のセットアップ

画面下の「メール」タブでは、受信トレイ（直近 14 日・最大 40 件）を AI が要約・分類して表示します。

- いちばん上に「まとめ」（今日まず知るべきこと最大 3 行）
- 「要返信」→ 学校・家族 / 仕事 / お金・支払い / 買い物・配送 / お知らせ / その他 / SNS / 広告 の順に表示（SNS と広告は折りたたみ）
- ゴミ箱ボタンで Gmail のゴミ箱へ移動（数秒間「元に戻す」可。完全削除はしない）

### 仕組み

| 部分 | 場所 | 役割 |
| --- | --- | --- |
| 画面 | GitHub Pages (`mail.js`) | 表示と操作 |
| サーバー | Google Apps Script (`gas/`) | Gmail の読み取り・ゴミ箱への移動、OpenAI での要約。10 分おきに新着を自動処理 |
| AI | OpenAI `gpt-5.4-nano` | 要約・分類・要返信の判定（新着・変更されたメールだけ） |

サーバーへのリクエストには、アプリでログインした Google のアクセストークンを付けます。
サーバーはそのトークンが「このアプリ用に、スクリプトの持ち主本人へ発行されたもの」か Google に確認し、違えば拒否します。
Gmail の権限は `gmail.modify`（読み取り・ラベル変更・ゴミ箱への移動）のみで、メールの完全削除や送信はできません。

### 手順（パソコン推奨）

1. https://script.google.com/ で「新しいプロジェクト」を作り、名前を `super-app-mail` などにする
2. 左の ⚙「プロジェクトの設定」→「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェック
3. エディタに戻り、2 つのファイルの中身を、このリポジトリの内容で丸ごと置き換えて保存
   - `appsscript.json` ← [`gas/appsscript.json`](gas/appsscript.json)
   - `コード.gs`（`Code.gs`）← [`gas/Code.gs`](gas/Code.gs)
4. ⚙「プロジェクトの設定」→「スクリプト プロパティ」→ プロパティ `OPENAI_API_KEY`、値に OpenAI の API キーを入れて保存
   - モデルを変えたいときは `OPENAI_MODEL` を追加（既定は `gpt-5.4-nano`）
5. エディタ上部の関数選択で `setup` を選び「実行」
   - 権限の確認が出たら許可する（「このアプリは確認されていません」→「詳細」→「（安全ではないページ）に移動」）
   - 実行ログに「準備完了」と出れば OK。以後 10 分おきに自動で新着を処理します
6. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
   - 「デプロイ」を押し、表示された **ウェブアプリの URL** をコピー
7. その URL を `config.js` の `MAIL_API_URL` に設定して公開する

`gas/Code.gs` を更新したときは、エディタに貼り直して保存し、「デプロイ」→「デプロイを管理」→ 編集（鉛筆）→ バージョン「新バージョン」→「デプロイ」で反映します（URL は変わりません）。

## ローカルで動かす

```sh
python3 -m http.server 8000
# http://localhost:8000/ を開く
```

## 仕組みと制限（v1）

- ログインは OAuth 2.0 のリダイレクト方式（トークンのみ・ブラウザ完結）です。
  iOS のホーム画面アプリではポップアップが不安定なため、ページ遷移で Google の画面に移動して戻ってきます。
- アクセストークンの有効期限は約 1 時間です。期限切れ後にアプリを開くと、
  自動で再取得を試みます（Google 側でログイン済みなら操作不要。画面が一瞬切り替わります）。
  再取得できない場合はログインボタンが表示されます。
- トークンはその端末のブラウザ (localStorage) にのみ保存され、外部サーバーには送信しません。
